Kopere Email

This plugin was developed to allow full customization of emails sent by Moodle, while maintaining a base template that standardizes the visual identity.

About Kopere Email

Objetivo
Pare de enviar “e-mails padrão feios do Moodle” e tenha um sistema de e-mails limpo, com marca e customizável.

Kopere Email

message_kopereemail é um output de mensagens baseado em message_email, criado para entregar e-mails consistentes e com marca - sem deixar de permitir que você crie HTML totalmente personalizado por tipo de notificação.

O que o plugin resolve (na prática)

O Moodle pode enviar muitas notificações diferentes, vindas de muitos plugins. Este plugin adiciona a camada que faltava: controle, consistência e customização sem alterações no core nem gambiarras no tema.

Padronizar identidade
Aplique um wrapper único para entregar layout, espaçamento, identidade visual e links consistentes.
Mensagens personalizadas por provider
Crie mensagens bonitas e personalizadas para eventos-chave (curso concluído, lembretes, avisos).
Controle de assunto + corpo
Sobrescreva assunto e conteúdo HTML em um único lugar, centralizado na administração.
Melhor comportamento na caixa de entrada
O modo resumo para conversas em grupo reduz spam e melhora a experiência.
Melhor parte
O Moodle continua enviando notificações normalmente - o plugin intercepta a entrega e aplica suas regras.

Como funciona

O plugin adiciona uma camada de customização sobre o fluxo de mensagens já existente do Moodle. Ele decide o que enviar com base no provider e no HTML disponível, depois padroniza a saída final com o wrapper.

Regra prática
  • Se fullmessagehtml existe → aplica o wrapper.
  • Se não existir → cria HTML simples a partir do texto e aplica o wrapper (se configurado).
Migração automática de configuração (na instalação)
Para evitar que estudantes recebam e-mails duplicados, o plugin pode migrar configurações para “assumir o lugar” do output padrão de e-mail.
  • Copia a configuração existente de message/email para message_kopereemail.
  • Reescreve flags de ativação dos providers de email → kopereemail.
  • Bloqueia providers (*_locked = 1) para manter consistência.
  • Desativa o processador antigo de e-mail em mdl_message_processors.
Importar / Exportar configurações
Mova wrapper + templates por provider entre ambientes (homologação → produção) ou entre sites.
  • Exporta o wrapper global.
  • Exporta mensagens personalizadas por provider (componente + nome).
  • Não sobrescreve preferências operacionais do Moodle, como flags enabled/locked.

Placeholders disponíveis

Templates usam placeholders no estilo Mustache. Use chaves triplas ao inserir HTML.

Comum
  • {{subject}}
  • {{fullmessage}}
  • {{{fullmessagehtml}}}
  • {{dates.now}}
Site
  • {{site.fullname}}
  • {{site.shortname}}
  • {{site.url}}
  • {{site.logourl}} / {{site.compact_logourl}}
Usuários destino
  • {{userto.id}}
  • {{userto.profileurl}}
  • {{userto.fullname}}
  • {{userto.firstname}} / {{userto.lastname}}
  • {{userto.email}}
Usuários origem
  • {{userfrom.id}}
  • {{userfrom.profileurl}}
  • {{userfrom.fullname}}
  • {{userfrom.firstname}} / {{userfrom.lastname}}
  • {{userfrom.email}}
Curso (quando detectável)
  • {{course.id}}
  • {{course.fullname}}
  • {{course.shortname}}
  • {{course.url}}
Expansão sugerida (ideias de roadmap)
Se quiser expandir a biblioteca de placeholders, estas são adições de alto valor que mantêm os templates simples:
  • Detalhes de conclusão do curso: data de conclusão, nota, URL do certificado, tempo gasto.
  • Metadados do curso: nome da categoria, data de início/fim, visibilidade, campos personalizados.
  • Conveniência do destinatário: idioma preferido, fuso horário, campos de perfil (subconjunto seguro).
  • Contexto do remetente: nome do papel no curso, departamento/campus (se disponível).
  • Formatação utilitária: datas pré-formatadas, links seguros, “resumo curto” de mensagens longas.
  • Links de CTA: URLs “Ir para o curso”, “Abrir atividade”, “Preferências de mensagens” como placeholders prontos para uso.
Dica de template
Insira HTML com {{{variable}}} (chaves triplas). Usar apenas {{variable}} pode escapar o HTML e imprimir tags como texto.

Boas práticas
  • Comece pelo wrapper: configure primeiro a identidade global.
  • Customize apenas os providers que importam.
  • Mantenha os templates objetivos e fáceis de ler rapidamente.
  • Valide a estrutura HTML (feche as tags corretamente).
  • Sempre teste depois de salvar.
Por que esta abordagem funciona
  • Sem modificações no core.
  • Sem gambiarras no tema.
  • Gestão administrativa centralizada.
  • Marca consistente em todos os e-mails.
  • Ajuste fino opcional por provider.
