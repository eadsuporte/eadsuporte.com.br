Entenda o cenário

Um plugin Moodle deve resolver uma regra de negócio, não apenas criar outra tela

Quando o Moodle padrão não atende uma rotina, a primeira etapa é entender quem utiliza o recurso, quais dados serão processados e que regras precisam ser respeitadas. Em muitos casos, vale avaliar primeiro as funcionalidades nativas e plugins existentes para evitar manutenção desnecessária.

Caso o desenvolvimento próprio seja justificado, pensamos em permissões, APIs, integração com o banco, atualizações, testes e documentação. O trabalho precisa ser sustentado após a primeira entrega, e não apenas funcionar em uma demonstração.

Dúvidas comuns

Perguntas antes de contratar

Preciso criar um plugin do zero?

Primeiro verificamos se recursos nativos ou extensões existentes atendem ao problema; código próprio precisa de benefício claro.

É possível adaptar um plugin que já uso?

Pode ser viável, dependendo de licença, qualidade de código, documentação e compatibilidade.

O código será entregue à instituição?

Direitos, licenciamento e condições de acesso precisam estar especificados na proposta.

Um plugin novo funcionará após atualizar o Moodle?

A arquitetura busca compatibilidade e manutenção, mas mudanças de API podem exigir ajustes futuros.
